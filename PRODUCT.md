# Product Context

## Product

Blazor MudBlazor Starter is a production-oriented starter template for building interactive Blazor Server applications with MudBlazor Material Design components, .NET 9, Docker, GitHub Actions, GHCR, Azure App Service deployment, and GitHub Pages documentation.

## Register

brand

The live application and documentation act as a public template showcase. Design is part of the product because the first job is to make developers trust the starter before they clone it. The UI should demonstrate tasteful MudBlazor usage, not just compile.

## Primary Audiences

- .NET developers evaluating a starter they can fork quickly.
- Teams that want a ready Blazor Server baseline with CI, Docker, deployment, dark mode, responsive layout, dialogs, and data-grid examples.
- Maintainers reviewing whether the project looks production-ready enough to reuse or recommend.

## Core Promise

A clean, reliable Blazor Server starter that feels familiar to MudBlazor users while showing enough craft to prove it is more than the default template.

## User Goals

- Understand what the starter includes within seconds.
- See live proof of common app-shell patterns: navigation drawer, breadcrumbs, dark mode, responsive behavior, data grid, CRUD dialogs, snackbars, and context menus.
- Find the next action: view docs, inspect GitHub, try the data-grid demo, or clone the repo.
- Trust the project as deployment-ready because CI/CD, Docker, health checks, Azure, security scanning, and dependency automation are visible.

## Brand Voice

Practical, technically confident, concise, and calm. It should sound like a reliable engineering template maintained by someone who cares about production details.

Avoid hype, vague SaaS promises, and placeholder tutorial language. Use concrete proof: .NET 9, MudBlazor 9, Docker, GHCR, Azure, CodeQL, 69K-row virtualized grid, health endpoint.

## Aesthetic Direction

Preserve the MudBlazor Material aesthetic: app bar, navigation drawer, cards or papers, clear elevation, Material icons, dark mode, and familiar component behavior.

The overhaul should not become a custom marketing page that hides MudBlazor. It should feel like a polished starter app using MudBlazor correctly.

## Anti-Goals

- Do not abandon Material Design or MudBlazor conventions.
- Do not turn the demo into a generic AI landing page with gradient text, glass panels, or repetitive icon-card grids.
- Do not remove demo utility. The Weather page must remain a convincing data-grid and CRUD demonstration.
- Do not over-specialize the template for one business domain. It should remain reusable.
- Do not leave starter copy such as “Hello, world!” as the primary message.

## Success Metrics

- Visitors immediately understand the starter's value and production scope.
- Primary actions are visible: GitHub, documentation, live demo sections, and clone command.
- The Weather page demonstrates high-density data-grid capability without feeling chaotic.
- Light and dark modes both feel intentional.
- The UI still reads as MudBlazor, but not as an untouched scaffold.
